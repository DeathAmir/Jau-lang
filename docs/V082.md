# Jau 0.8.2 — Native Stability & Safe Codegen

Copyright: **DeathAmir Jau @ DeathAmir 2026 (C)**

Jau 0.8.2 is a correctness-first release. The VM and native backends now use the same entry-point semantics: a zero-argument `func main()` is invoked automatically exactly once unless source explicitly calls `main()` at top level.

## Stability fixes

- Fixed native PE executables that successfully linked but silently skipped user `func main()`.
- Fixed the same entry-point inconsistency in VM/bytecode execution.
- Disabled VM and AOT optimization transforms for 0.8.2. `-O0` through `-O3` remain accepted for command compatibility, but code generation uses safe semantics until optimizer transformations receive dedicated regression coverage.
- Added native AOT `print("literal")` support through the platform C runtime while retaining integer printing.
- Kept unsupported native value classes explicit: dynamic string/array operations that are still VM-only return compiler errors instead of silently generating broken executables.
- Invalid source is expected to return a diagnostic and non-zero exit code rather than crash.
- Native `.jaux` objects remain binary linker inputs; package wrapper Jau source is parsed separately.
- Native `extern func` declarations continue to bind discovered COFF symbols without namespace-mangling the C ABI name.

## Copyright behavior

Jau tools emit `DeathAmir Jau @ DeathAmir 2026 (C)` on stderr so normal program stdout remains usable by scripts. Generated native assembly also embeds the notice, which carries it into native output artifacts without changing user program stdout.

## Required regression examples

```jau
func main()
{
    let a = 10;
    let b = 20;
    print(a + b);
    print(a * b);
    print("Jau native OK");
    return 0;
}
```

This must work without a trailing `main();` in VM mode and in Windows x86/x64 native builds.
